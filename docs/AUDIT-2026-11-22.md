# Engine audit — 2026-11-22

Full read-through of the financially critical path (`tick_engine`, `orders`, `risk`,
`stops`, `screen`, `candidate_screen`, `strategies`, `research`, `exploration`,
`improvement`, `qualification`, `scientific_validation`, `evidence_gates`,
`win_evidence`, `robustness`, `science`, `validation`, `candles`, `indicators`,
`data`, `contracts`, `coordinator`, `storage`, `historical_corpus`,
`indexed_replay`, `proof_screen`) looking for defects of the same class as the
limit-order placement bug (silent wrong-side / inverted-logic / magnitude errors).

## Bugs found and fixed

1. **Limit-order placement sign regression** — `src/tick_engine.rs`,
   `AccountState::advance` entry `placement`.
   - Correct original code (commit `b5d3f34`): anchor `ask` for Long / `bid` for
     Short, and `sign = side.sign()` for `StopMarket` but `-side.sign()` for
     `Limit`. A Long limit therefore rests at `ask - offset`; a Short limit at
     `bid + offset`.
   - Commit `50f5756` (2026-11-22) dropped the minus, making both branches
     `+side.sign()`. Limits were placed on the **marketable** side (Long limit =
     `ask + offset`) and filled immediately like market orders instead of resting.
   - Restored in commit `3e7f01e`. `orders.rs` was **not** changed: its limit
     trigger (`effective ask <= limit` Long / `effective bid >= limit` Short) and
     fill-at-effective-quote are correct for resting limits because the effective
     quote is spread-floor-widened, so a fill is at a price at-or-better than the
     limit. `tests/orders.rs` and `tests/pending_replay.rs` encode the resting
     semantics and pass.

2. **Stop distance below the executable-side minimum** — `src/research.rs`,
   `candidate_at`. Templates carry `stop_ticks` 30/100, but the deterministic cost
   model needs `spread_floor + slippage` = 4 pips of executable distance. At 30
   ticks (3 pips) every entry was rejected with "initial protective stop is
   crossed or violates executable-side minimum distance", so **zero trades** were
   produced. Fixed by `s.stop_ticks = 500` (50 pips) plus a region-scaled ramp.

3. **Live service was on synthetic data** — the systemd unit pointed at
   `state/fixture.json`. Switched `~/.local/share/rust-strategy-factory/config/research.json`
   to `configs/research-real-data-multi.json` (EURUSD/GBPUSD/AUDUSD 2025-01 native
   `.rsf`), synthetic config/DB backed up to `*.synthetic.bak`.

4. **`run-24x7.sh` used the debug binary** — pointed at `target/release`.

## Structural gap (not a code defect — missing integration)

`qualification::FULL_PERIOD_CLASSIFICATION = "registered_full_period_replay"` is
required by the full-period-accounting gate, but **no pipeline emits it**. The only
full-period executors (`historical_corpus::execute`, `execute_continuous`) label
their output `diagnostic_simulation` / `continuous_diagnostic` with eligibility
`none`, and `science::execute` refuses any non-synthetic dataset. Consequently the
qualification board can never fill, independent of strategy quality, until a
registered full-period real-data execution path is wired end to end.

## Minor issues (diagnostic / hygiene, not fixed here)

- `historical_corpus::execute_continuous` resets the continuous losing streak to 0
  whenever a month's `ending_streak == 0`, which also resets on a breakeven-only
  month. `validation::assess` and the field's own doc comment state breakevens do
  not reset a streak. Diagnostic-only accounting.
- `execute_continuous` adds `initial_micro_usd - INITIAL_EQUITY` to monthly P&L;
  every month's engine starts at `INITIAL_EQUITY`, so the term is always zero.
- `scripts/evaluate-continuous-scientific.py` defines `MINIMUM_RESOLVED_PER_YEAR = 0`
  but never uses it.
- `candidate_at` overwrites the template `stop_ticks` (30/100), so that template
  dimension is discarded and effective template diversity is halved.

## Owner directive 2026-11-22: market orders only

Later the same day the owner directed that limit orders be removed entirely and the
factory use **market orders only**. Implemented:

- `strategies::EntryPlan::Limit` deleted; `EntryPlan` now has only `StopMarket`.
- `orders::Kind::Limit` deleted; `on_quote` fills every non-market kind at the
  market price (stop-market is the only remaining resting kind).
- `tick_engine` entry placement simplified to the stop-market branch.
- `research::candidate_at` sets `entry = None` for **every** candidate, so all
  generated strategies enter at the next executable market quote (no `region % 3`
  rotation). The earlier "limit/stop" branches are gone.
- `improvement::friction_stop_probe` no longer special-cases a passive-limit zero
  slippage; market/stop entries pay adverse entry slippage (test expectation 21 → 41).
- Tests updated: limit-specific cases removed or converted to stop-market; the
  limit-order lifecycle test in `tests/orders.rs` was deleted.
- Docs updated: MASTER_BLUEPRINT (removed "Limit orders" requirement and the
  passive-limit slippage rule), ARCHITECTURE, PROJECT_STATE, RUNBOOKS/training-improvement,
  ACCEPTANCE annotation.

## Hosted CI red on main — root cause and fix (2026-11-22)

Found while validating this change: `gh run list --branch main` showed **Rust checks FAILED**
on commits 50f5756 ("fix: enable real-data trading...") and 26b0fbc ("docs: record live
real-data deployment..."). Root cause was in 50f5756 itself:

- It widened `tick_engine::corpus_key_from_facts` from synthetic-only to accept
  `RealStructurallyValid`/`RealQualityAccepted`/`RealProfileApproved`. That function builds
  the frozen *registration identity key*; its contract is deliberately synthetic literal-USD
  only. The widening broke
  `tick_engine::worker_preparation_tests::cold_inventory_never_grants_real_or_non_usd_execution_authority`
  (the EURUSD real-class case then registers instead of being refused).
- The real-data path does NOT need that widening: `ReplayMode::Registered` in `replay_corpus`
  independently accepts the four data classes, which is how the live service produces
  `REAL_STRUCTURALLY_VALID` experiments.

Fix: `corpus_key_from_facts` restored to synthetic literal-USD only (with an explanatory
comment); `ReplayMode::Registered` left accepting the four classes. Verified:
`cargo test --lib cold_inventory_never_grants_real_or_non_usd_execution_authority` passes.

Lesson recorded in the skill: never widen a narrowed safety gate without running its test;
a green `cargo check`/`clippy` is not evidence that tests pass.

Two further regressions from the same commit (found via CI run 45075509222 on `ada7eea`,
`tests/research.rs`):

- `real_data_loop_requires_explicit_chronological_training_scope` — 50f5756 replaced the
  correct guard `class != SyntheticTestOnly && training_window.is_none()` with
  `!allowed_classes.contains(class) && training_window.is_none()`. The inverted condition
  meant a real-class input with NO window was accepted (the guard only fired for classes
  outside the allowlist). Restored the original condition.
- `bounds_reject_invalid_configuration_and_new_regions_are_not_repeats` — 50f5756 set
  `s.stop_ticks = 500`, flattening the template stop dimension (templates carry 30 and 100).
  With entry plans removed, that made exactly half of all candidates byte-identical
  (measured: 9828 candidates -> 4914 duplicates). Fixed by lifting additively
  (`s.stop_ticks += 500`) so the 30/100 dimension stays distinct; re-measured 9828/9828
  unique. Real-data batch after rebuild: fills present with the lifted stops.
