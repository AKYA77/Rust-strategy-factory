# Trusted invocation-local checkpoint continuation

Branch: `codex/trusted-session-checkpoints`, based on main `e16063713bd4`. Independent of unmerged PR #1; its tested branch is preserved. A worker retains at most one private account state, conversion hasher, previous timestamp, event count and committed checkpoint digest. The state is minted only after the engine successfully commits its own checkpoint, then retained only after successful lease yield. It cannot be deserialized from stored JSON or supplied through the public API. Current source/path/specification, experiment/build/configuration, control and lease checks still run. The complete stored checkpoint chain is mechanically verified. Only an exact owning experiment/source/cursor/digest match can skip prefix account transitions. Mismatches, cold sessions, external progress, holds, errors and explicit release lose this authority and retain sequential semantic validation. Full artifact traversal and byte/order verification remain mandatory; this is not persistent authenticated seek or reduced source IO.

One account slot per worker moves into the active transition without cloning its receipt vectors. Dynamic cross-round assignment reserves the largest receipt budget for every worker, or discards retained slots before work, matching the existing conservative candle reservation. Successful-step replayed/skipped-event counters expose actual account work without implying total IO, equal CPU allocation or OS RSS enforcement.
