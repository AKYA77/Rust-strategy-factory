# Bounded foreground retry waiting for campaign rotations

The rotation loop waits only for pure eligible retry hints from the current frozen campaign region. It uses stored source policy/origin/deadline, child/coordinator leases, lifetime/queue/journal caps and actual server time. It does not reset deadlines on restart, infer retryability from error text or write retry observations while polling. Source-error outcomes and operator/terminal holds never auto-resume. The source supervisor repeats actual admission checks transactionally before work.

A scheduler-idle resume compares the same control epoch and origin in one immediate transaction. An operator pause on an already idle rotation changes intent and invalidates the old resume. Parent/source holds remain independent. The command bounds visits1..10000, checks to twice that plus one, cumulative cooperative wait0..3600000ms,50ms interruptible slices and a100ms minimum wake interval. Waiting budgets cover cooperative waits, not hard filesystem/kernel deadlines. Policies are hashed at invocation start and rechecked during waits; retuning cannot silently replace the running invocation's policy.

One unit test covers stale idle epochs and operator override. Three actual CLI tests cover zero/finite wait budgets, unchanged retry deadlines/journals and no processes across restart, eligible wake then actual permanent-error hold without relaunch, and operator/SIGTERM interruption. Typed busy provenance in these fixtures is explicitly synthetic fault metadata, not an acquired market/history event. The actual awakened engine failure is retained as permanent. Full Rust verification follows before publication; no qualification or production service survival is implied.
