# Durable generated corpus backlog

Status: IMPLEMENTED_SYNTHETIC_CORE. `src/corpus_search.rs` combines deterministic candidate_at generation with the authoritative corpus step/batch path. The separate materialized research Driver remains a one-worker coordinator; supplied static corpus batches remain available.

The search identity freezes source/artifact and initial experiment identities, generator method, seed, candidate budget, queue width, costs, execution budgets and compute revision. All candidate grammar slots in the bounded range are validated before a new search is registered. Generation refusal fails admission without automatic retry. Real/protected execution and non-USD conversion remain refused by the existing corpus/registry gates. Operator worker counts and admission-pressure thresholds may vary without changing frozen financial inputs.

Immutable queue bodies retain candidate index/family/strategy/complete experiment key. Generation advances only with transactional queue admission, at most32 slots at a time, and replenishes only after the admitted batch has no unfinished slots. Canonical duplicates share verified receipts; slot counts never mean new tick simulations. The key configuration hash now uses one shared helper with corpus execution rather than a second identity recipe.

A separate token/attempt/expiry coordinator lease fences admission and queue publication. Replaced coordinators cannot publish progress or clear replacement tokens. Child experiment/checkpoint leases retain their existing fencing. Already committed child results survive a missing queue update and are recovered through exact keys without extra experiment attempts. Controls apply at safe boundaries; a concurrent pause/stop can leave committed child results waiting for later queue reconciliation. Stop is irreversible. Worker errors remain explicit and pause the affected search.

Quotas:64 search definitions,4096 global generated slots,16 MiB queue-body bytes,64 KiB per immutable job definition and512 characters per stored error. Queue width is1–32; active pool limits remain1–16 workers plus concurrent object caps. Corpus operator configs now enforce the1 MiB limit on bytes actually read, including files that grow during reading. No retention/reset API bypasses these bounds.

API/CLI tests cover full scalar receipt parity, drain-before-replenish/reopen, coordinator replacement/control fencing, child-publication-before-queue-update recovery, immutable-body/cursor corruption, verified paused backups, explicit worker errors, CLI pause/resume/exhaustion, actual SIGKILL at a writer wait and SIGTERM/restart. The sixth Chromium suite verifies authenticated inventory/snapshots/controls, CSRF/origin refusal, exact exports/token redaction, desktop/mobile/restart and corrupt-state nonpublication. These cover specific failure points, not exhaustive disk-full/power-loss/reboot acceptance.

Remaining: explicit bounded error requeue/attempt history, fair multi-corpus scheduling, larger artifact/retention lifecycle, representative generated-search worker measurements/adaptive selection, live OS resource enforcement, real/full-history conversion and complete scientific qualification. Exhausted means the declared candidate budget is spent; it never means independently qualified or all research finished.
