# Durable pause origin, epochs and bounded control history

Schema11 adds a verified per-search control head and immutable transition detail. A new search starts running at epoch0. Worker-error publication, exhaustion, explicit requeue and operator state changes update search state/head/history atomically inside the existing immediate transaction. Every effective transition advances an exact state epoch. An operator pause overrides a worker-error pause even when the state remains paused; repeating the same operator pause or reasserting running is idempotent. Paused searches expose operator, worker_error or legacy_unknown origin and an exact timestamp only when actually observed.

Search coordinator claims capture the epoch and publication fences verify it in addition to token, attempt, expiry and running state. Controls retain nonce revocation. Old actors cannot publish after a pause/resume, including an old nonce restored into token columns with a newer verified epoch. Child experiment leases, execution keys, checkpoint rows and terminal result hashes remain independent. Manual requeue retains the existing per-slot three-event limit and original-error journal, and clears pause intent through an explicit requeue transition.

Each head/body is capped at4096 bytes and content-hashed. Immutable transition bodies form a contiguous hash chain with per-search epoch uniqueness. At most128 detailed transitions per search and4096/8 MiB globally are retained. Once detail cannot be admitted, the current verified head continues advancing with an explicit omitted count; detail does not silently resume after a gap. Full history is never claimed when omitted. This preserves operator stop/resume at logging capacity. Corrupted/unverifiable state still fails closed. These are application-local integrity checks, not independent authentication against a database owner rewriting all state.

Migration preserves frozen configurations/results and revokes in-flight search coordinator nonces. Previously paused searches become legacy_unknown with no fabricated pause time. Old running/stopped/exhausted states remain as observed. Stop old processes and retain a verified pre-upgrade snapshot/matching binary before schema upgrade: old schema10 binaries must refuse schema11, and already-open unsupported old operator applications cannot be made safe merely by a version marker. Migration is not a repair path for a missing head in an existing schema11 registry. Financial source/build identities are never retuned by migration.

Authenticated status/inventory and existing exact exports expose decimal-string epochs/counts/times, pause origin, at most32 recent transition receipts and explicit history completeness. Dashboard cards distinguish operator and worker-error pauses. Registry integrity and verified native/staged backups include and check these tables. Historical transition detail starts at control tracking, not at an invented original creation date.

Six additional Rust tests cover pause override/idempotence and backup preservation, capped detail with stop still available, immutable/missing history refusal, schema10 unknown-origin migration versus missing schema11 state, migration nonce revocation with unchanged keys, independent epoch fencing, and racing operator pause versus fenced worker publication. Existing actual worker-error/CLI requeue integration now checks origin/epoch clearing. Actual Chromium checks operator and worker origins, exact transition exports, desktop/mobile/restart and existing security/control/requeue guards.

This completes the control prerequisite, not a retry supervisor. Worker_error describes where an error was returned; it does not establish a transient retryable cause. Next preserve typed worker failure categories, then implement an opt-in frozen policy with durable backoff, bounded decisions and owned-process lifecycle. Never infer retry eligibility from human error strings or auto-resume operator/legacy pauses. See0015-supervisor-control-boundaries.md for the remaining acceptance matrix.
