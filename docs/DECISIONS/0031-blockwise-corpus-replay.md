# Pinned block artifacts in corpus replay

Corpus v2 binds dataset identity, full consumed-file fingerprint and block root for every block artifact. It supports mixed block/native inputs; v1 identity and serialization remain unchanged when no block roots exist. Range/authenticated index roots are never omitted from a v2 research identity. Native chunks retain their100K admission cap, while block artifacts can declare up to2M events without retaining the artifact's decoded quote array.

`visit_blocks` exposes a distinct borrowed quote-block type whose manifest describes the complete artifact. It does not masquerade as a partial Dataset. Inspection, causal candles/multi-frame signals and the authoritative account transition now consume these blocks, checking cross-block/cross-artifact profile/source/class/event order. Complete successful source traversal/fingerprint validation remains required before publishing state. The materializing `visit_chunks` API remains available under explicit caps.

Account checkpoint cursors still count complete artifacts. Blocks inside an artifact never publish a partial cursor or compare the saved prefix prematurely. Reopen still recomputes and verifies the saved source/account prefix; this is not fast-seek restart. Native and block layouts preserve full financial receipts, with separate physical corpus identities. The materialized CLI/review loader also accepts capped block artifacts and preserves canonical experiment identity across lossless encoding changes.

Six new tests cover all-eight candle/signal contexts and legacy identity, exact nonzero market/stop/limit replay receipts, mixed-layout reopen/cursor boundaries, late-corruption checkpoint/attempt preservation, actual CLI descriptors/canonical cached reuse and a100001-event artifact with256 decoded quotes resident at once. The corpus browser regression passes. Real/protected/non-USD corpus replay, production codec selection, representative physical-cold performance and large-feature/checkpoint scaling remain unfinished.
