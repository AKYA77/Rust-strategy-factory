# Fenced foreground corpus campaigns

Schema20 adds independent campaign control heads and bounded immutable region-advance chains to the frozen schema19 plans. New plans start running without starting work; existing schema19 plans migrate paused with epoch zero. Pause/resume/stop increments the epoch and revokes the parent nonce. Repeating the same state retains a current lease. Stopped/exhausted heads cannot resume. Controls do not fabricate historical timestamps or immutable transition history; the current epoch/state and region-advance chain are the persisted observations.

An explicit foreground command runs at most10000 outer checks, each invoking at most one ordinary search round. The returned `rounds` count includes held, pressure and terminal checks; it is not a child-execution or new-simulation count. Each visit verifies the complete frozen scope and current region identity, checks current disk/RSS admission, claims an independent campaign lease, rechecks the cursor, and invokes at most one ordinary bounded source search round. Parent fencing applies before and after the child and at publication. Only a verified exhausted source permits atomic append-plus-cursor advancement. Its exact redacted status digest enters the immutable chain. Next regions register lazily; source holds and existing child leases/results remain authoritative. Canonical duplicates reuse exact receipts.

Parent pause or lease loss can leave the current bounded child round committed; no campaign advancement or next region follows without a valid parent fence. Publication failure rolls back the advance and retains completed child evidence for reuse. Crash leaves an expiring parent lease and no invented completion. Restore revokes only copied campaign leases alongside existing actors. Signal handling stops between bounded rounds. Source stalls, hard OS deadlines, equal CPU allocation, background service installation, cross-input campaign rotation and automatic retry supervision are separate unfinished work.

Four additional unit tests cover competing leases, pause/resume stale-nonce fencing, stale release, terminal controls, schema19 held migration, injected append/update rollback with exact child reuse, and real managed restore/source fence independence. An actual multi-region process workflow covers pressure before claim, pause/restart, held-source preservation, lazy replenishment, full scalar replay parity, exact chain exports, exhaustion without extra attempts and backup parity. No synthetic campaign qualifies and no new statistical family is created beyond the frozen horizon.
