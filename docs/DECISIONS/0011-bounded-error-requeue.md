# Bounded error requeue and prior-error history

Only generated slots in execution-error state can be requeued. The search must be paused without an active coordinator lease. A request selects at most32 eligible slots in candidate-index order, limited by free space in the frozen queue width. Each slot permits at most three explicit requeues. Running, stopped and exhausted searches refuse the operation; committed terminal experiment results are never reset.

One immediate transaction appends the stored prior-error text to an immutable per-slot hash chain, clears the current error into queued state, and resumes the search with its old coordinator token cleared. Frozen strategy/key/source/budget bodies and generation cursor remain unchanged. Child experiment tokens/attempts/expiry/checkpoints are untouched. Active children therefore report busy until they yield/expire; already committed child receipts are reused without new attempts. Requeue records count operator requeue events, not new strategies, financial trials or proof of subsequent execution.

The journal uses a stable integer event key, per-slot sequence1–3, previous-record hash, exact stored error (at most512 characters), bounded body4096 bytes and update/delete refusal triggers. Global caps are10000 journal records and40 MiB bodies. Status, registry integrity and backups validate the chains. These are local application integrity records, not independently authenticated scientific evidence or protection against an external database owner rewriting the whole registry.

CLI and authenticated CSRF-protected dashboard controls start no process. Operators must run the original frozen build/configuration to execute queued work. Retry is useful for transient same-input failures; changing an execution budget or strategy requires a new identity. Current errors can clear after requeue, while prior errors remain visible/exportable. No requeue grants qualification.

Tests verify three-event exhaustion without mutation, immutable history and hash-consistent prefix forgery refusal, backup/VACUUM preservation, one-winner concurrent requests, pending-slot capacity, active-child lease preservation/no busy-spin and cached published-child recovery without extra attempts. Actual CLI/browser paths verify controls, guards and exact prior-error exports. Disk-full/power-loss and production supervision acceptance remain unfinished.
