# Durable owned-parent invocation observations

Schema16 retains at most128 parent invocation records, with private owner tokens, compute/config/policy-input digests, frozen execution limits and actual parent PID metadata. Admission occurs before spawning. A child PID attaches exactly once through the owner fence. PID fields never grant a handle or establish liveness after restart.

After reaping, the parent atomically commits an immutable terminal summary (at most8192 encoded bytes). It retains the full report digest, separate complete child-report digest and observed child-session receipt hash without copying large reports into registry metadata. The public command returns the complete report; operators who need it must retain that output separately. Hashes bind the observation, not a claim that the full report can be reconstructed from the summary. Error text in summaries is bounded; the original report digest still identifies original bytes/values. A failed terminal write leaves the record unclosed. Abrupt parent death is not silently reconciled into a fabricated child exit.

`corpus-owned-invocations DB` and `corpus-owned-status DB ID`, authenticated read-only inventory/detail routes and dashboard raw exports expose exact IDs/PIDs/times. No PID or executable action endpoint exists. Snapshot request ownership prevents stale exports. Integrity and backup validate/preserve records, terminal hashes and unclosed state. Metadata admission at capacity refuses new owned invocations while existing completion remains available. Schema migration revokes prior coordinator nonces without relabeling research keys.

Three new Rust tests verify owner/attachment/terminal fences, backup parity, rollback on injected terminal-write failure, corruption refusal and capacity. Actual owned-process tests now verify persisted CLI parity and report-digest binding. Chromium/Axum/SQLite checks cover actual parent invocation history, auth/read-only/ID validation, exact exports, restart/mobile and corrupt-record refusal. Parent-death service recovery, kernel enforcement and target-VPS operation remain unverified.
