# Typed corpus worker admission failures

A worker pool now returns a failure-kind vector aligned with its existing input-order job results. Successful jobs have no failure kind. Actual SQLite DatabaseBusy/DatabaseLocked codes observed during classified registry admission produce registry_admission_busy. Ordinary execution strings remain unclassified. Missing thread results are worker_interrupted and are not implicitly transient. Legacy error metadata becomes legacy_unknown. Only registry_admission_busy is a retry candidate; this is a classification hint, not an enabled policy or permission to resume a pause.

The existing string-returning Registry::open API delegates to a classified constructor without changing its human diagnostic text. Typed SQLite codes are retained where explicitly propagated, including the search-control admission transaction. Older helper paths that return strings remain unclassified, even when their text resembles SQLITE_BUSY. No human-message parsing broadens retry eligibility. Some true busy failures may therefore conservatively remain unclassified.

All worker connections initialize before threads start. If admission fails, the report contains zero started workers, an explicit startup failure and aligned error/kind entries for every supplied job. No child experiment is claimed by that aborted pool. Some earlier connection/schema initialization may already have completed. Source/budget/duplicate-job preflight refusals remain outer errors. Callers must inspect report jobs/failure counts; a returned report is not completion evidence.

Schema12 adds current error kind and a hash binding the search ID, slot, immutable job hash, kind and exact bounded error message. Error slots require verified provenance; other states must not retain it. Worker-error publication writes kind/message/hash atomically with queue state and the schema11 pause transition. Corrupt kind/hash combinations fail closed. Manual requeue preserves the prior kind in immutable prior-error history and clears current failure fields. An absent optional prior-kind field reads as legacy_unknown; old record bytes/hashes are not rewritten. No terminal receipt, child lease, configuration or financial key is reset.

Migration labels existing error messages legacy_unknown without guessing from text, preserves frozen job bodies, and revokes in-flight search coordinator nonces. Retain a verified pre-upgrade snapshot/matching binary and stop older processes before schema upgrade. Older schema11 binaries refuse schema12. This is not a repair path for missing columns in a current registry. Checksums detect local inconsistency; they are not independent authentication against a database owner rewriting all data.

Authenticated search snapshots expose current kind, a conservative retry-candidate flag and prior-kind receipts. Cards show recent error kinds and explicitly state automatic retries are unavailable. Actual execution-budget failures are tested as unclassified/nonretryable. Real SQLite writer contention is tested as typed admission busy with zero child registrations, followed by successful same-job execution after releasing the lock. Backup/migration, hash tampering, legacy body identity and CLI/browser prior-kind exports are covered.

Automatic retry/backoff and owned-process supervision are still unfinished. Next freeze an opt-in operational policy and apply it atomically only to current worker_error pauses with eligible typed failures and matching state epoch. Preserve the existing three-requeue/capacity/history limits, hold on clock rollback/backoff/unknowns and never override operator or legacy-unknown intent. No classification grants scientific eligibility or establishes that a new simulation ran.
