# Managed private registry snapshots and new-path recovery

Managed recovery uses a private700 directory beside the canonical registry and600 files; symlink/nonregular/unprivate entries refuse. Labels are bounded lowercase identifiers, never caller paths. Defaults cap16 retained entries including incomplete attempts,2GiB logical root bytes,512MiB databases,4096 receipt files/1GiB and a sampled128MiB free-space reserve. OS file locking serializes operations across processes. Admission is not reserved space or a kernel/filesystem deadline; source growth and write failures can leave retained incomplete evidence. No deletion API exists.

Online SQLite backup includes committed WAL and copies only the snapshot's referenced immutable receipt files. The completed copy is fully verified and sealed in DELETE journal mode without live sidecars. A bounded hash-checked manifest binds database/artifact bytes, schema/build, exact counts and operation lineage; the manifest publishes last through a no-replace hard link after synced data. Listing verifies manifest metadata only and explicitly reports content freshness false. Explicit verification checks actual bytes, offline state and current-schema integrity without modifying the snapshot. Older schemas receive byte/SQLite verification; full current validation occurs on a migrated new copy.

Restore always targets a new managed label. It rechecks source bytes, copies bounded files, migrates only the destination, revokes copied unfinished experiment/coordinator leases and validates the new registry. Terminal results/tokens remain intact; unclosed process records remain unknown without fabricated completion or PID ownership. The original snapshot is reverified afterward. No active database replacement, service activation, credentials/source-archive copying or automatic worker start occurs. A restored workspace becomes mutable only through a separate operator cutover; later changes invalidate its sealed receipt until independently handled.

CLI supports list, backup, verify, restore and local path lookup. Eight tests cover committed WAL/file receipts, stale/new actor fences, source immutability, privacy/names/no-replace, corruption/sidecars/malformed caps, incomplete/byte/collision admission, symlinks, unclosed session preservation, older-schema migration only in the copy and actual CLI workflows. Raw recovery directories are Git-ignored. Dashboard controls remain next work; production reboot/disk-full/cutover and target-VPS acceptance remain pending.
