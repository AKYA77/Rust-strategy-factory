# Frozen corpus candidate ranges

Corpus operator files accept an optional unsigned `start_index`, default zero. Search definitions bind a nonzero start into their immutable identity. Zero is omitted from persisted definitions, preserving legacy hashes. Every queue slot deterministically selects `candidate_at(start_index + slot, seed)`; exact financial experiment keys match scalar replay and canonical duplicates retain normal cache reuse. Status reports both the local slot and absolute candidate index as decimal strings.

Checked range arithmetic and bounded grammar admission refuse overflow/exhaustion before opening a registry. Registration verifies every declared candidate before queue insertion. Integrity recomputes the frozen definition for each persisted slot, so an alternative valid strategy with a re-signed local receipt cannot substitute for the declared range. Search count, global queue and receipt budgets remain unchanged. Registering a later range cannot resume an operator-held earlier search.

Three Rust unit tests cover legacy bytes/identity, explicit zero, deterministic later strategies/keys, registration idempotence, held-source preservation, backup/reopen, re-signed valid candidate substitution refusal, overflow and grammar exhaustion. An actual CLI test drains a later range, compares complete replay receipts to the scalar path and proves reopening adds no attempts. This is a campaign prerequisite; durable cross-region replenishment and complete campaign-wide trial accounting remain unfinished. Ranges and synthetic receipts do not grant qualification.
