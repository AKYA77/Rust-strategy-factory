# Pinned owned-worker inputs and region execution

Owned parents now freeze typed operator configuration, effective operator configuration, policy and expected search identities before spawning their same-executable child. The bounded internal child protocol reopens current inputs and compares the complete pin before any registry/session/source writes. A region override applies only after validation; it never rewrites the operator file or creates a derived configuration. Configuration, base start, execution-limit or policy changes between review and child startup refuse rather than starting a different source.

Explicit regional owned execution requires the expected frozen search identity. Parent admission validates it before registry creation. Existing wall/output/resource observation, cooperative stop, owned-handle kill/reap and terminal history fences remain shared. The parent report and persisted bounded summary retain the pin; summary validation binds its effective configuration, policy and source to the invocation. Absent/null pins preserve legacy receipts; no schema migration or terminal rewrite occurs. These are synthetic training workers, not qualification or hard kernel deadlines.

Two actual process tests cover changed inputs/limits/policy, unknown fields and incorrect identities before registry creation, unchanged operator bytes, valid pinned child execution, expected regional source/session identity, reaping and persisted pin exports. One adversarial storage test covers mismatched pin fields, rollback, backup and re-signed summary substitution. Existing owned/fleet supervision regressions remain required. Campaign ownership/publication integration and multi-input fair scheduling remain next work.
