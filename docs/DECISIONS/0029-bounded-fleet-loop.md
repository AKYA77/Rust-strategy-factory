# Bounded foreground fleet waiting and idle recovery

`corpus-fleet-loop DB FLEET POLICY LIMITS MAX_VISITS TOTAL_WAIT_MS` runs independently once explicitly started. Bounds are1..10000 visits, at most twice that many checks plus one, and0..3600000ms cumulative monotonic waiting. Zero wait reports the frozen deadline and exits. The browser starts no process. Installation, survival after abrupt parent death and production service acceptance remain separate.

A pure retry planning path is shared with actual source requeue admission. Scheduling hints verify typed busy/error/lifetime/capacity/history/child-lease/terminal constraints and frozen policy/deadline without writing events or changing jobs. Hints grant no admission: the actual source transaction repeats all checks later. Permanent failures and active/terminal children do not cause long retry sleeps. Already configured permanent source holds start no further child. A100ms minimum wake interval prevents immediate idle spinning.

Only a complete verified scheduler-idle fleet epoch can resume. Waiting polls controls/signals in short intervals without filling the retry journal. Operator/legacy/terminal intent, changed epoch, exhausted wait/check/visit budget, no eligible retry or signal exits cleanly. Before each owned visit, ordinary fleet/source resource guards and child limits apply. Frozen-policy mismatch refuses before further claim/work. Restart retains original source deadlines and idle intent.

Six new tests cover pure preview/deadline/clock/no-write/type/active/terminal checks, actual bounded wait/restart/no journal spam, actual idle wake and execution followed by permanent failure hold, operator intervention, SIGTERM and retune/invalid-budget refusal.
