# Invocation-owned corpus preparation sessions

`CorpusBatchSession` retains at most one immutable candle context per worker across bounded rounds. Its binding includes the registry path, complete ordered source bindings/candidate identities and every round/concurrency limit. A changed invocation releases all old contexts before allocating replacements. Each round still opens independent registry connections, joins every owned scoped worker and returns with no thread or lease owned by the session. The session retains only preparation buffers. Explicit `release`, drop, failed admission, worker ownership failure or any failed job drops all retained slots.

The foreground `corpus-batch` loop owns one session and explicitly releases it when the loop ends, including normal budget, operator/source hold, returned error and signal exits. A separate CLI process starts with empty slots and recovers from the persisted registry checkpoint. Generated search/supervision callers retain their existing one-round API and do not gain an undeclared cross-call cache. Concurrent sessions have independent ownership; declared caps apply per invocation and do not establish a global RSS/OS controller.

Preflight still inspects every distinct full source binding each round. Reuse still decodes and fingerprints current artifacts before registry admission, and the account pass independently checks complete consumed artifacts before publication. Saved account prefixes are recomputed against the source; no checkpoint state becomes authoritative merely because candles are warm. This is preparation reuse across resume rounds, not fast-seek account recovery.

Three integration tests verify independent sessions, explicit release, changed-limit eviction, aggregate admission failure, holds, source mutation without changed attempts/checkpoints, restored input and failed-job cleanup. A self-hashed forged account checkpoint is refused with a warm session while its prior evidence remains unchanged. A real two-process CLI restart completes multiple source artifacts with exact nonzero stop/limit receipts matching materialized replay; the last in-process round builds no new context. The existing parallel multi-round test now exercises session ownership, aggregate candle bounds and full scalar receipt parity. Other replay, mutation, control, lease and corruption tests remain unchanged.

Benchmarks, when cited, are complete synthetic CLI pipeline measurements with exact receipt/count parity and separately checked cache reuse. Representative real/full-history scale, checkpoint-aware seek, persistent production resource enforcement, lifetime inventory/queue scaling and independent scientific qualification remain unfinished.
