# Worker-local corpus preparation lifecycle

Each bounded corpus batch worker now owns at most one immutable prepared candle context. The binding includes the invocation base path, full specification including artifact paths and operational event caps, canonical primary timeframe and aggregate candle cap. Strategy rules, features, stops, costs and receipt budgets remain independently validated/prepared for each candidate. Changing a binding releases the old candle buffer before constructing another. No cross-worker mutable cache, persisted cache authority or unbounded frame inventory exists.

On reuse, all currently resolved source artifacts are fully decoded/fingerprinted and their profile/class/order rules checked before deriving a registry key from the prepared report. A failed current-byte check evicts the slot before registration or claim. The account pass independently validates every artifact again before checkpoint/result publication. A source change after admission therefore cannot publish from stale candles. Restoring bytes permits recovery under normal lease fencing. Saved account prefixes are still recomputed and compared; fast-seek remains unfinished.

Preflight shares inspection reports only for exactly matching full source bindings and drops that bounded metadata inventory before workers start. Duplicate candidate identities and concurrent object caps still refuse before opening the registry. Each worker connection remains independent. The registered step compares its freshly verified key against the stored experiment before replay without repeating the same key inspection. Held, busy and cached jobs start no preparation/account pass. Cached source eligibility still requires fresh verification.

Batch reports expose preparation builds, actual replay reuses, attempted current-byte checks and the maximum retained candle count of an individual worker. These are object observations, not total memory, physical-cold evidence or hard OS enforcement. Features, quote blocks, retained result reports and other allocations are additional. Slots end with the bounded round; persistent invocation/shared-round lifecycle is the next separate task.

Three unit tests cover mutation before registration, mutation injected after admission without publishing a checkpoint or receipt, restored-source/expired-lease recovery, relocation despite unchanged semantic identity, changed timeframe/cap and failed replacement eviction. Actual CLI execution compares complete market/stop/limit and alternate-frame receipts with nonzero resolved trades, observes two builds/two reuses and verifies cached restart without builds. Existing parallel rounds now assert bounded per-worker preparation and complete scalar parity; a feature-budget failure followed by a healthy candidate exercises reuse without poisoning the context.

Real/protected/non-USD execution remains refused. Synthetic benchmarks measure the actual fresh-registry CLI pipeline and separate cached checks; complete receipts and registry counts must match. They establish no source approval, independent trials, full-history qualification, production throughput or default-policy promotion.
