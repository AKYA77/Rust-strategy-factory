# Owned foreground corpus child lifecycle

`corpus-supervise-owned CONFIG POLICY DB ROUNDS WAIT_MS LIMITS` runs this same executable's `corpus-supervise` command as an owned child. It accepts no arbitrary executable. Parent limits require1..86400000 wall milliseconds,0..60000 graceful shutdown milliseconds and1024..1048576 captured bytes per output stream. Search/policy and disk/memory preflight run before child creation. Existing frozen source/retry identities and child session semantics remain authoritative.

The child sends its session identity on the parent's private stderr pipe. The parent verifies session source and actual spawned PID before a cooperative stop request. A signal, sampled wall budget or output fault requests stop and then escalates only through its owned `Child` handle after grace. Normal and escalated exits are reaped. RAII also kills/reaps on ordinary parent error unwinding. No stored PID is used as a kill target. Abrupt parent death remains outside RAII guarantees.

Independent pipe readers cap retained output, drain excess without unbounded allocation and detect read failures; parsing requires a complete bounded child report. A truncated report is never exposed as partial JSON. Status distinguishes cancellation reason, delivered stop, forced kill, actual exit code, byte counts and observed session state. Grace is sampled; hard kernel/filesystem deadlines are not claimed. The command is an explicit foreground mechanism, not an installed persistent service.

Six new tests cover capture/handshake boundaries, limit refusal, actual normal child exit, cooperative wall-budget stop and terminal receipt, actual parent SIGTERM with zero-grace forced child termination/reaping, bounded output overflow, pressure-before-registry creation and restart/deadline parity. Existing foreground signal regression passes with the nonfatal stderr handshake. Durable parent invocation receipts, parent-death recovery/resource monitoring and production service acceptance remain unfinished.
