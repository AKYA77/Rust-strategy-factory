# Verified source facts without candle aggregation

`corpus::source_facts` now computes precisely the source inputs needed for a frozen execution key: complete pinned corpus identity, profile, declared class/source, count, exact global ordered event fingerprint, first/latest event and maximum resident quote block. It fully visits native/blocked artifacts and preserves global order, metadata and consumed fingerprint checks. It constructs no candle streams, hashes or vectors. Existing full inspection and authoritative account preparation retain all their original candle/casual checks.

SourceFacts has private fields, immutable getters and no deserialization. A compile-fail check prevents a supplied JSON report from minting it. Prepared contexts can derive the same facts from their internally verified report. Every reused source-facts or warm frame consumer still verifies actual current artifacts under exact source/path/operational bindings. Key construction now explicitly compares the facts' corpus identity against the specification. Canonical strategies, costs, individual/aggregate budgets, synthetic literal-USD gates, leases, protected reservations and semantic account-prefix recomputation remain unchanged. These are observations, not source/scientific approval, current-byte authority or fast-seek proofs.

`corpus-source-facts SPEC` exposes only the observed metadata. The existing full-horizon check independently compares its nine source fields with full seven-frame inspection and confirms there is no candle field. A new integration test compares every fact across all eight symbols in native/blocked layouts, exact CLI JSON and mutated-artifact refusal. Existing cold source mutation, current-path/event-cap refusal, real/non-USD gates, both compile-fail cases and all full financial/restart/forgery tests remain required.
