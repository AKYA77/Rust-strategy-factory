# Current architecture

One Rust package with an embedded Axum/HTML/JavaScript dashboard and no frontend runtime server. Application code forbids unsafe Rust; bundled SQLite and ZSTD plus dependency internals form explicit native/unsafe trust boundaries. Python scripts are development/operations tools, outside the research hot path.

`data` validates normalized original-order bid/ask events and content/provenance identities. `native` stores bounded uncompressed SoA bytes; `compressed` adds exact bounded ZSTD restoration. Both reconstruct owned event structs. `parquet_store` adds a strict four-integer-column Parquet/ZSTD cold baseline with compact-Thrift/page size preflight before upstream allocation. Full-history block access/streaming and measured real-corpus codec selection remain missing. `candles` publishes closed UTC candles on seven frames only after subsequent real events; `indicators`, `strategies` and `stops` provide canonical typed causal rules, shared bounded features, higher confirmations and frozen initial ATR distances.

`contracts`, `risk`, `orders` and `tick_engine` execute one authoritative ordered L1 full-fill assumption with exact integer prices/USD millionths/volume, explicit event-aligned conversions, executable bid/ask costs, pending stop/limit entry intents, immutable risk reservations, adverse stops/deadlines and receipt/equity accounting. `tick_index` remains a separate fixed-barrier prototype. `indexed_replay` adds an experimental complete market-entry USD/integral-cash engine with ordered drawdown summaries and strict fallback;512 whole-replay comparisons and engine-level measurements exist, and `indexed_policy` adds explicit training-only batch/API context binding, lazy authorized setup and independent sequential audit/failure blocking. Its full-factory timing is inconclusive; autonomous/scientific/default selection is not enabled. `screen` provides conditional single-position M1 barrier sets/audits; `candidate_screen` adds bounded hypothetical USD market-entry M1 cash estimates, explicit uncertainties and runtime-selected versioned shadow/audit policy comparisons bound to full experiment and child-review identities. `proof_screen` adds opt-in training-only exact fixed-market no-entry rejection, mandatory deterministic tick audits, durable contradiction blocking and transaction-fenced publication; default/shadow candidates still run ticks. Proof-only training reviews explicitly label mathematical zero-entry evidence.

`storage` owns SQLite WAL schema/migrations, unique complete experiment keys, fenced leases, immutable result hashes, cross-dataset instrument/time OOS/final reservations and verified online backups. `research::Driver` is an actual standalone persistent one-worker loop with fair input rotation, durable cursor/region expansion, controls, soft state-file backpressure and bounded improvement jobs. Unix SIGINT/SIGTERM finish a safe checkpoint and release the coordinator lease. `research::evaluate_batch_report` and the manual `batch-experiments` CLI now share validated immutable preparation, primary candles and bounded features for up to64 same-frame candidates, preserving scalar keys/receipts and one lease at a time. Automatic batch scheduling, worker pools/hard resource control/supervision are unfinished.

`improvement`, `training_diagnostics`, `exploration` and `training_review` retain immutable training-only parent/proposal/current-build evaluation links, seeded bounded scalar/structural probes, factual diagnostics and descriptive comparisons. Scientific/OOS/final receipts cannot authorize adaptation. Automatic children do not recursively schedule descendants.

`science` freezes chronological training/three-month folds/final ranges and actual synthetic replay evidence. `robustness`, `uncertainty`, `diagnostics` and `regimes` provide descriptive conditional probes/breakdowns. `validation` implements numerical research gates. Independent evidence completeness, dependence-aware acceptance, qualification decisions and diverse ranking are unfinished; real scientific execution remains blocked and synthetic never qualifies. Registry-local exposure protection cannot track external tools or copied registries.

`dashboard` reads actual persisted research/experiment/protocol/training evidence, provides authenticated CSRF-protected run controls, bounded paginated experiment/training history and exact raw exports. Unsafe-JS integer views defer to raw receipts. Data management, operational controls, complete pagination/metrics and qualified-ranking UI are partial. Empty qualification boards are honest but are not a completed ranking subsystem. Default binding stays authenticated loopback.

`scripts/operate.py` supplies content-addressed local releases, checked notice bundles and verified staged new-path backup/restore. Non-root systemd templates declare resource limits; static/local acceptance does not prove live host enforcement or reboot recovery. Target-VPS deployment remains separately authorized. The owner identifies the GitHub repository as public; do not change visibility or commit private archives/credentials. Complete license/security review and production operations acceptance remain pending.

Requirement-to-source/test reconciliation and the remaining implementation work are maintained in IMPLEMENTATION_QUEUE.md. SOFTWARE_INCOMPLETE, full historical research acceptance and target-VPS production verification remain distinct states.

`machine_evidence` now persists exact recomputed archive/calendar bindings in the catalog and supports explicit live revalidation without granting approval. `review_authority` provisions a small local credential/scope/signing trust root; `data_approval` records immutable authenticated review decisions with stale-head fencing, revision/expiry/revocation handling and a live artifact gate for the exact reviewed calendar scope. Supplied `data_review` assertions remain separate. Synthetic data/research-only profiles cannot receive scientific approval. Catalog snapshots preserve metadata/signatures but exclude the authority secret; live authentication requires that separately protected root. No real protected science or strategy qualification is enabled by this data gate.

`corpus` adds ordered exact-byte/provenance-bound native chunk inventory and bounded read-only inspection beyond one artifact. `candles::Stream` retains seven independent forming candles using the same publication transition as batch builds; no chunk boundary finalizes a candle. Global event/candle fingerprints and cross-chunk quality counts remain exact. A caller event cap is checked before native row allocation; fingerprinting uses the same consumed byte stream. This does not yet integrate full-history feature computation or authoritative account replay, compressed blocks or durable stream checkpoints.

Compiled compute identity also binds the import/coverage/catalog/review/evidence/authority/approval/corpus modules explicitly. Actual rebuild probes and the CI guard verify new data-source changes cannot silently retain the old identity, while CSS-only changes remain excluded. This conservative identity update preserves old immutable receipts; it does not retroactively approve them or claim new quantitative benchmark results.
