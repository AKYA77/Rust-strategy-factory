# Candidate M1 shadow estimates

`research::evaluate` and chronological window evaluation persist `candidate_screen_audit` alongside the unchanged authoritative `tick_replay`. Zero-signal candidates retain the existing proven rejection. Default/shadow signaled candidates still run ticks; the optional exact proof policy below can skip only certified impossible entries. Estimate errors are explicit unavailable diagnostics and cannot suppress replay.

`candidate_screen::estimate` version `m1-hypothetical-cash-v1` models market entries for USD-quoted profiles. It takes the first actual quote strictly after signal publication, applies the executable spread floor and adverse entry slippage, freezes fixed/causal ATR distances, and uses the existing exact initial-risk/marked-margin/volume-grid reservation against hypothetical evolving cash. It charges both commissions and classifies positive **net** money as a win. Losses stay uncapped.

This is an approximate trajectory, not candidate performance bounds. A possible stop uses adverse bar extrema with separate exit slippage; a target uses its requested price. A collision selects the stop proxy and records unknown order. Entry-bar extrema can precede entry. Short effective-ask extrema lose bid/ask correlation. The model reserves the whole estimated exit bar, so overlapping signals differ from actual intrabar availability. All these uncertainties are explicit. It never emits invented `Trade` receipts or exact stop execution timestamps. At a partial deadline bar it uses the first real quote at/after24h as a proxy and marks that an earlier protective hit may have happened. Gaps are not filled with synthetic quotes.

Pending entries and non-USD conversion paths are unsupported and promote. Unclosed final coverage, window boundaries, unavailable entry quotes and stop warmup stay explicit. Only bars published strictly before an exclusive evaluation end may inform estimates. The model caps total visited bars at25000/candidate; exhausted and unresolved totals are partial and cannot shadow reject. This is not a complete memory/CPU limit: dataset verification, M1 reconstruction, signal iteration and stop preparation remain bounded by existing input/grammar limits outside the visit counter.

Unresolved outcomes produce unknown false-negative status. ## Fixed market-stop necessary-condition proof

`screen::market_stop_proof` supplies an independently re-verifiable quote/equity-independent proof for fixed market entries only. With raw stop distance D, executable-side minimum M and declared minimum entry friction F=(spread-floor+entry-slippage)*pip, the risk contract requires D+signed(mark-entry)>=M, while actual executable pricing guarantees signed(mark-entry)<=-F. Therefore D<M+F proves every such entry infeasible. Equality cannot prove failure. This is distinct from an actual order-rejection receipt and does not say an entry is feasible when the proof is absent. Wider observed spreads, commissions, margin and conversions can add failures.

Proofs bind exact canonical strategy/profile/cost hashes and are re-derived on verification. ATR and pending entries are refused. Research persists the proof **after** actual replay and fails publication if any actual entry contradicts it; no execution skip is enabled. Existing actual-rejection training hypotheses remain based on actual tick receipts. Tests compare96 independent executable-distance cases across all8 profiles, both directions,3 cost levels and2 observed spreads; equality, tampering and unsupported policies are checked. Runtime proof-based skipping and compatible training evidence semantics remain future work.

## Runtime policy and comparable context

`research::evaluate_configured` accepts `EvaluationOptions` with the optional policy, feature budget and optional frozen evaluation window. Existing evaluate/window APIs retain conservative defaults. Policy validation happens before registration; zero-signal and tick results both store the selected policy (null for omitted legacy choice). Explicit policy hashes include a versioned domain and the original full data/profile/cost/conversion/feature context. Research-loop identities include the optional selection. Diagnosis/parent identity already binds it, so restart/review reuse cannot silently switch policies. This adds configurable shadow diagnostics, not an execution reject mode.

## Opt-in training proof policy

`limits.proof_policy` (see `config/research-proof.example.json`) is separate from approximate `shadow_policy`. Version `fixed-market-proof-screen-v1`, seed and audit basis points enter the complete experiment/campaign configuration and comparable child contexts. The default remains omitted/off. Only authorized training protocol/stage combinations may enable it; real data also requires an explicit training window. Scientific/protected evaluation cannot enable it.

For a nonzero-signal candidate with the exact fixed-market proof, a deterministic BLAKE3 sample of the complete experiment identity selects actual tick audit (default10%, mandatory nonzero1..10000bps). Unsampled cases publish `ProvenNoMarketEntry`, `proof_rejection:true`, no `tick_replay`, and the complete verifiable proof/specification. Scoped quote/currency validation, eligible next-market-quote checks and distance arithmetic still run; invalid inputs cannot be hidden by the proof. Sampled cases retain the real empty-position replay and actual order rejections, with the same rejected candidate disposition. Unsupported/unproven cases run ticks. Approximate OHLC shadow failure never skips ticks.

A contradiction appends a durable audit-failure event and fails the experiment. Further proof-policy calls, including cached reuse, fail closed in that registry; a transaction guard prevents a pending proof rejection from publishing after the marker. The coordinator pauses. Default actual replay remains available. There is no automatic reset/bypass API; preserve the registry and investigate a failure before any new acceptance. The marker survives backup/restart, but cannot protect external tools/copied registries. Current marker lookup scans event actions; full-history metadata-scale performance and dedicated aggregate audit dashboards remain pending.

Training diagnosis verifies exact proof/context and explicitly labels a proof-based hypothesis rather than inventing observed rejections. Comparable review re-derives proof zero-entry money, preserves policy/configuration, and records `net_basis` explaining that zero is not an executed zero-return trade. This optional field preserves old evidence hashes when absent. An actual child at the declared minimum floor still requires real replay and may fail under wider spread/risk/margin. The browser labels skipped trades, shows the proof and exports exact receipts; no tick numerical assessment is fabricated.
