# Experimental full-accounting indexed replay

`indexed_replay::replay` is a build-and-run convenience API; `indexed_replay::Index::build(...).replay(...)` reuses one immutable scoped quote index across candidates. It returns the complete existing `Replay`, an explicit used/fallback flag/reason and query counters. This module is experimental. Defaults remain sequential; explicit training-only batch/API selection is described below. The old `tick_index` remains a separate fixed-barrier prototype.

## Supported exact cases

The fast path supports market entries, including frozen fixed/ATR initial distances, for USD-quoted profiles with literal event rates1/1. Every volume step must produce integral USD millionths per price tick: `contract_units * step_micro_lots * tick` is divisible by `price_scale`. All marked/filled prices remain on that tick grid, so account movement is exactly linear without discarding the P&L rounding contract. Scoped timestamps must be nonnegative and leave room for the24h deadline. The index caps input at2million events.

Pending entries, non-USD quotes, nonliteral USD rates, fractional cash grids and unsupported spans use the sequential path. A failed convenience-API attempt also reruns the authoritative implementation, preserving its error ordering. Direct index construction is a preflight API and may refuse before replay. Every scoped FX/quote is validated; invalid FX outside an exclusive scope is not consumed. An immutable borrow binds quotes, costs, conversion stream and window throughout reuse.

The shared replay prelude verifies dataset, exact source candles, frozen causal mask/prefix, canonical strategy, stop preparation and cost contract for both engines. Costs, risk sizing, price/fee arithmetic and protective levels use the existing functions. No narrower spread, missing fee, loss cap, favorable target improvement, fabricated tick/gap, changed holding rule or liquidity claim is introduced.

## Ordered accounting summaries

Blocks contain actual effective bid/ask extrema plus **ordered** maximum bid drop and ask rise. Combining earlier/later blocks preserves cross-boundary peak-before-trough relationships. This differs from inferring order from OHLC. Full/partial ranges retain exact original event order and original sequence/timestamps.

On the integral cash grid, each position's marked equity is a linear transform of its executable quote. The range summary therefore gives exact internal drawdown and cross-range drawdown from the existing account peak. Commissions remain in their actual entry/exit cash updates. MFE/MAE include the actual exit quote, while equity/peak uses post-fill cash at that quote, matching the reference rather than recording a favorable pre-limit mark. Deadline lookup precedes any protective hit at the first actual quote at/after24h. Target fills remain at the requested level; market/stop/deadline fills use the actual executable quote and separate adverse slippage. Same-quote reopening is blocked; a signal published on an exit event may enter on the next actual sequence, including a timestamp tie.

The result preserves every trade field, balance/marked equity/drawdown, rejection, unresolved/pending state, provenance/fill assumption and evaluation window. Scientific eligibility is unchanged. Successful indexed results remain experimental; explicit factory selection now adds context binding and independent sequential audits below. Default promotion still needs representative performance and broader acceptance.

## Explicit factory training policy

`limits.indexed_policy` version `training-shared-index-v1` selects the experimental path for `batch-experiments`; `config/research-indexed.example.json` shows the synthetic setup. The library `EvaluationOptions` carries the same policy. Version, mandatory nonzero audit basis points1..10000 and seed bind the full experiment/batch configuration hash and survive exact comparable parent/child review. Omitted policy preserves the legacy configuration formula. Default/source scientific execution remains sequential; configured independent/scientific stages refuse experimental selection. Real data requires an explicit training window. Autonomous `research` currently refuses this policy because checkpoint-aware index lifecycle/supervision is unfinished; the manual batch API is supported.

Each batch owns a lazy immutable index cell over its one input/cost/window. Quote summaries are built only after a nonzero candidate is authorized/registered and leased, never to probe protected data first. Cached, zero-signal and unaudited proof-only skips need no index initialization. Unsupported capability is also cached for sequential fallback. Replays still independently verify source candles/frozen signals, and proof-rejection audits always use the sequential implementation.

A deterministic sample binds the complete experiment identity to the declared policy. Selected successful indexed results are compared against the entire independently executed sequential `Replay` using canonical cryptographic hashes, not just profit/exit kind. Metadata records actual path, fallback, block work, selected audit and both hashes. These implementations share contracts/validation; this is execution-path verification, not independent scientific/source evidence. Failed/mismatching reference results or failed postconditions append a durable failure marker. Future indexed calls/cached reuse refuse, and an immediate-transaction publication guard blocks an already-leased accepted result after the marker. Default sequential work remains available. No automatic reset is exposed; preserve evidence and investigate. A partial covering index now bounds marker lookup independently of ordinary event volume; production startup/write-scale acceptance remains open. The authenticated overview shows separate persisted proof/indexed failure states, retained across service restart. Absence is explicitly not audit coverage or qualification. Aggregate audited-result/false-negative counters remain open. Protection is registry-local and cannot cover external tools/copied databases.

Comparable reviews inherit the immutable parent policy and configuration. Their evidence labels an audited index match or an unaudited experimental replay explicitly; scientific/OOS/final adaptation remains forbidden. Manual comparable reviews may build per candidate and are not a speed claim. The authenticated detail view/export shows the selected policy and actual reference-audit evidence.
