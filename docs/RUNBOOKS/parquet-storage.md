# Bounded Parquet/ZSTD cold baseline

The explicit baseline uses Apache parquet60.1.0, without Arrow or other default codec features, with ZSTD enabled. It is an optional file representation accepted by the actual CLI/research/protocol paths. It does not select a production hot format, supply full-history streaming, or approve source data/profile/coverage.

```sh
cargo run --locked -- pack-parquet state/input.rsfz state/input.parquet
cargo run --locked -- inspect state/input.parquet
cargo run --locked -- unpack-parquet state/input.parquet state/restored.json
```

`pack-parquet` accepts existing JSON/native/RSFZ/Parquet dataset input; its output must be new. Exactly four required INT64 columns retain original row order: UTC millisecond `timestamp_ms`, logically unsigned64 `sequence`, signed exact fixed-point `bid` and `ask`. Sequence bits round-trip through the physical INT64 representation, including u64::MAX. Profile scale and the complete original manifest are stored in the single `rsf.dataset.v1` metadata entry. No float prices, timestamp rounding, sorting, synthetic gap repair or category promotion occur. The format is an internal exact dataset schema, not an arbitrary-provider Parquet importer.

The writer uses Parquet1.0 data pages, PLAIN integer encoding, ZSTD3, no dictionaries/statistics,8192-row groups and64KiB data-page targets. Each row group is256KiB of raw four-column event values. Publication uses a bounded temporary writer, file/parent sync and a no-replace hard link. Output failure cleans only its own temporary path; existing artifacts remain untouched.

Reader limits:128MiB captured file,2MiB footer,1MiB dataset metadata,2,000,000 events,4096 row groups and8192 rows per group. Data is captured once, including a growth cap, and the same immutable bytes are validated/decoded. Before upstream metadata allocation, a small allocation-free compact-Thrift preflight caps list/map counts, binary length, work/depth, and requires exactly five flat schema elements (root plus four required integer leaves). This prevents declared nested-schema expansion before comparison. Before any page decompression, preflight checks ranges inside captured data, one supported PLAIN data-page type, at most8192 values and exact `raw_bytes=values*8`, with compressed page/header limits. Dictionary/external paths and unrelated schemas are refused. The upstream reader then validates exact logical schema/counts and the original dataset/profile/order/content hashes are checked after reconstruction. These defenses are not an OS RSS quota or complete parser/security audit.

Tests cover all eight synthetic profiles, ties/full unsigned sequence range, multiple row groups, invalid logical schema/missing or forged metadata, truncated/malformed footer bounds, oversized page-allocation declarations, structural bad quotes even under recomputed content hashes, and no-overwrite cleanup. CLI tests prove JSON/native/RSFZ/Parquet inputs reuse one exact experiment and review context. Actual browser research and its frozen protocol now load Parquet input before normal persistence/control/lineage/export/restart checks.

The selected new source/license inventory and verified Cargo archive checksums are in SOURCE_REVIEW/2026-11-13-parquet.json. Apache/third-party notices are retained in THIRD_PARTY_NOTICES/parquet.txt. Existing RSFZ stays pinned to zstd0.13.3; Parquet adds the0.14.4 Rust wrapper with the same resolved native zstd-sys C package. This explicit dependency cost preserves previously verified RSFZ behavior. New installs bundle all required notice files and reject incomplete distributions; historical release manifests retain their checksummed bundle. No implementation was copied from an upstream project. Native/unsafe dependency boundaries and the complete advisory/license audit remain separate review work.

## Same-corpus performance evidence

Build `cargo bench --locked --bench storage_pipeline --no-run`; pass the reported executable and NEW output/resource paths to `python3 scripts/measure.py`. The executable compares native/RSFZ/Parquet on the same eight20000-event synthetic instruments, three candidate complexities, five rotated repetitions and two cache conditions. It verifies all dataset, experiment-ID and complete persisted result hashes, nonzero trades, exact new-experiment counts and separate cached-result reads. The research stage includes the currently incomplete signal-only M1 rejection, authoritative sequential replay and SQLite persistence; this is not completed candidate-level net screening or scientific qualification.

The file-local advisory-eviction condition uses Python `os.posix_fadvise(POSIX_FADV_DONTNEED)` outside Rust operation timers, without global cache changes. Its successful return does not prove physical disk/controller cache coldness. Actual `/proc/self/io` load read bytes are recorded. Physical-cold, representative-real-corpus, full-history and target-VPS acceptance remain pending. Whole-child CPU/RSS/I/O includes setup, equality checks, hint helpers and all trials; it is not a per-codec peak-RSS claim. RSFZ encoding includes its public workflow's intermediate native materialization, so encoder scopes are explicit.

For this exact fixture, total native/RSFZ/Parquet sizes are5127903/688609/618546 bytes. Warm median load+new-pipeline times were517.515/530.934/534.987ms; advisory-eviction medians544.244/599.365/546.723ms. Each batch completed24 new experiments and17660 synthetic trades, with24 later cached reads counted separately; all30 batches matched complete results. Whole-child peak RSS26208KiB. Release binary grew from7239768 to9067208 bytes relative to the preserved ea0c6cc artifact. Parquet is retained for the required standard cold-storage baseline and smaller fixture size; these small differences do not establish a universal speed advantage or justify changing production defaults. No automatic codec selector is enabled. Further codecs must justify their dependency/maintenance costs using relevant workloads.
