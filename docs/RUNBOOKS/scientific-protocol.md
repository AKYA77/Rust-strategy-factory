# Frozen scientific protocol execution

Status: implementation evidence only; reports always remain `INSUFFICIENT_EVIDENCE`. This is not complete statistical qualification. Use synthetic fixtures for software verification while independent gates remain incomplete. The executor rejects non-synthetic data before reserving or exposing the final interval. Real final execution remains blocked until independent prerequisites are implemented.

`validate-protocol <input-config.json> <plan.json> <registry.sqlite>` accepts exactly one input using the research-loop configuration format, with explicit event-aligned conversions when required. `protocol-report <registry.sqlite> <protocol-id>` reads a hash-verified persisted report. Authenticated dashboard protocol buttons display the same evidence.

A plan contains `training`, `folds`, `holdout`, `candidates`, `costs`, and `trial_budget`. Intervals contain UTC integer `start_ms` and exclusive `end_exclusive_ms`. Each fold has `train`, `test`, and `embargo_ms` (at least 86400000). Tests span three complete UTC calendar months beginning at midnight on the first. Training expands from the same initial start, precedes its test with the embargo, and never shrinks. Tests do not overlap. Final holdout begins at least 24 hours after the last OOS interval ends. Plans permit 1–32 distinct canonical candidates and 1–16 folds; the preregistered trial budget must cover every candidate and derived robustness case. It is not a count of independent trials.

The definition binds the frozen plan, dataset/provenance/profile/conversion identities, engine/features/signals and compute revision. Final reservation occurs before any evaluation. Each candidate receives distinct persisted selection-training, fold-prior-training, fold-OOS and protected-final experiments. Recovery reuses exact experiment receipts; a published report is immutable. Retuning, registered prior OOS exposure on the same instrument/time, including other content hashes, and altered final experiments are rejected. Identical numerical histories on different instruments have independent reservations. Legacy global reservations remain conservatively global. Registered overlapping instrument/time exposures and final reservations are checked across dataset hashes, blocking revised-history aliases. Schema6 also reserves OOS ranges transactionally across aliases/protocols before evaluation; outside registration and reservation cannot both succeed. Exact immutable recovery is permitted, range-set changes are rejected, and failed multi-range transactions leave no partial reservations. Expanding prior training within the same frozen protocol may reuse earlier OOS time. External tools and independent registry copies remain outside this protection.

Every window starts flat with prior-only feature warmup and uses no quotes at or beyond its end. Unresolved positions remain explicit. Pooled OOS statistics describe independently reset fold accounts; summed P&L is not a compounded full-period account. Failed windows, unresolved positions, actual result references and missing requirements remain visible. Empty synthetic date ranges cannot prove coverage.

`npm run test:browser` creates a new synthetic protocol through the real CLI, verifies immutable reuse, and reads its report through the dashboard. `cargo test --locked --test science` also executes nonzero synthetic OOS trades, rejects retrospective exposure/retuning, validates calendar boundaries and detects report tampering. These tests remove their private state and do not qualify any strategy.

Still required: corpus-wide exposure and coverage/approval evidence, uncertainty/multiplicity safeguards, cost/neighborhood/regime robustness, frozen full-period financial qualification and diversity ranking. Do not infer these from successful window execution.

Frozen reports now include conditional Hoeffding/Bonferroni net-win diagnostics using the declared trial budget. Assumptions remain unverified; the diagnostic cannot qualify a candidate. See [method and limitations](../DECISIONS/0002-conditional-uncertainty.md).

They exclude intratrade marks and unresolved positions and must not be presented as complete account drawdown. Missing replay stays explicit; empty bins have no expectancy estimate. Each bucket retains an exact net-P&L numerator and resolved-trade denominator. These UTC bins do not establish broker/DST session approval or market-regime robustness.
