# Native uncompressed SoA baseline

This is a bounded lossless interchange/storage foundation, not the selected production hot format or the required Parquet/ZSTD cold baseline. Research execution currently reconstructs the existing in-memory event representation. Compression, memory mapping, direct SoA execution, full-history streaming and representative real-data measurements remain unfinished.

```sh
mkdir -p state
./target/release/rust-strategy-factory fixture EURUSD state/fixture.json
./target/release/rust-strategy-factory pack-native state/fixture.json state/fixture.rsf
./target/release/rust-strategy-factory inspect state/fixture.rsf
./target/release/rust-strategy-factory unpack-native state/fixture.rsf state/restored.json
```

All output paths must be new. `inspect`, `candles`, `evaluate`, `experiment`, and research/protocol input files accept native datasets with the `.rsf` extension. Other dataset extensions continue to select JSON. `unpack-native` explicitly decodes a native input regardless of extension. Research configuration still uses the `dataset` path and the same event/byte/training/conversion budgets. For example, replace `../state/fixture.json` with `../state/fixture.rsf`. Conversions remain separate explicit event-aligned JSON; no FX rates are inferred.

The bytes encode `RSFNAT01`, a little-endian u64 count, a u32 metadata length, exact typed profile/manifest JSON, and four complete little-endian columns in this order: timestamp i64, sequence u64, bid i64, ask i64. A trailing BLAKE3 covers all preceding bytes. The exact file length is `52 + metadata_length + 32 * count`. There is no lossy conversion, price rounding, sorting, delta convention or fabricated quality flag. Format version, lengths, checksum and dataset identities are checked before use. Sequence values retain the entire u64 domain.

Limits are two million events, one MiB encoded metadata and a 64 KiB column staging buffer. Header/file-length checks precede event allocation. Decode validates the exact stream checksum and original manifest/profile/event invariants; checksums do not replace structural validation, source approval or authenticity. Trailing/truncated input and changed headers are rejected. Invalid/quarantined datasets cannot be published through this writer. All existing source/archive/parser/category metadata remains unchanged; native encoding never promotes data readiness.

Publication writes a random new temporary inode in the destination directory, flushes/syncs it, hard-links without replacement, syncs the directory and removes the temporary name. Existing artifacts remain untouched on an overwrite attempt. Preserve immutable original source archives separately: this wrapper is not a replacement for source/license/acquisition evidence. Disk-full/crash-injection and production filesystem acceptance remain pending.

Four native tests cover all eight profiles, tied event order, exact provenance, chunk boundaries, high unsigned sequences, hostile lengths, checksum corruption, truncation/trailing bytes, independent structural validation and no-overwrite cleanup. The real CLI test packs/unpacks and replays a nonzero trade through native input, then reuses the JSON experiment identity. Chromium acceptance runs the actual standalone research loop using native input before inspecting its persisted results.

A bounded lossless ZSTD wrapper is now available as `.rsfz`; see compressed-native.md for framing, exact native restoration, source/licenses, window/output/file caps, CLI equivalence and component measurements. The native format itself is unchanged. This wrapper does not supply full-history streaming, Parquet comparison or a selected production codec.

## Ordered multi-chunk corpus inventory

```sh
rust-strategy-factory corpus-create data/corpus.json data/chunk-000000.rsf data/chunk-000001.rsf
rust-strategy-factory corpus-inspect data/corpus.json
```

Creation describes and verifies existing native chunks; it never concatenates or overwrites them. The new specification is published through the existing synced no-replace JSON writer after a complete ordered inspection. Paths initially use canonical local locations. Moving unchanged artifacts and updating only their paths preserves corpus identity; each ordered chunk's exact consumed-byte BLAKE3 and dataset/provenance identity remain mandatory. Original archives/catalog receipts stay separate. A path list is not evidence of source completeness or approval.

The versioned specification contains `version: "ordered-native-corpus-v1"`, `max_chunk_events`, and ordered `chunks` with `path`, `dataset_identity`, `file_hash`. The CLI uses65536 events/chunk; the API permits1..100000, at most10000 chunks and a16MiB loaded specification. Relative paths in an edited specification resolve against its directory. Native count limits are checked before allocating rows. The bounded reader fingerprints the exact descriptor stream being decoded rather than reopening the path for a later hash. Existing native/RSFZ/Parquet loading defaults are unchanged; compressed corpus blocks remain future work.

Inspection retains one quote chunk plus seven incremental candle states and compact metadata/hashes. It compares the exact profile, declared class and source across chunks, validates each immutable artifact, and refuses backward timestamps, reused/reset sequence IDs, revisions or corrupt bytes. Gaps/ties/repeated quotes are observed across boundaries without inserting/deleting events. Global ordered-event and each timeframe's candle hashes equal the ordinary canonical JSON-array hash. The shared candle publication transition emits only when a later real quote crosses a boundary; chunk ends never finalize or discard a forming candle. No final unfinished bucket is emitted. All seven timeframes work across chunk boundaries.

Output is bounded counts/fingerprints with exact decimal sequence strings, not an in-memory full-history candle/tick array. Per-chunk metadata/validation allocations and the specification add memory beyond the quoted resident-event bound. There is no catalog/classification promotion, missing-range inference, provider acquisition/resume, scientific approval or strategy/account replay streaming. The existing experiment/research loaders retain their materialized input limits. Future streaming features/replay must consume this ordered path without resetting account, causal warmup or publication state.

`corpus-candles SPEC_JSON TIMEFRAME MAX_CANDLES NEW_OUTPUT_JSON` exports verified closed candles under an explicit1..2000000 candle cap. A failure publishes no output. This retains one quote chunk and a bounded candle vector; it does not yet provide checkpointed feature/account replay.

`corpus-replay SPEC STRATEGY MAX_CANDLES FEATURE_CELLS MAX_RECEIPTS NEW_RESULT` executes synthetic literal-USD input through the ordinary authoritative account transition. Context/receipt caps refuse before publication; no quote concatenation or conversion array is retained. Results match ordinary full receipts in fixtures. Real/protected input, non-USD conversions, durable checkpoint recovery and registry orchestration are not enabled by this command. No performance acceptance is implied.

Experimental block storage: `pack-blocks INPUT.json|INPUT.rsf NEW.rsfb BLOCK_ROWS`, `block-inspect FILE.rsfb`, `unpack-blocks FILE.rsfb NEW.json` and `block-range FILE.rsfb PINNED_ROOT START_ROW COUNT`. Retain the root from a complete verified inspection in the caller's frozen artifact context; do not treat a root supplied by an unverified file as approval. Row range exports use exact integer strings. Limits are2M events,4096 blocks,1..8192 rows/block and1..65536 returned rows/range. Full scans verify canonical event identity; partial ranges verify only touched blocks under the pinned root. Corpus integration and representative/cold comparisons remain pending; no default format changed.

Corpus descriptions accept `.rsfb` artifacts and pin roots in version2; mixed native/block inputs are supported. `corpus-create-bounded NEW_CORPUS.json MAXIMUM_ARTIFACT_EVENTS CHUNK.rsf|CHUNK.rsfb...` makes the admission cap explicit (up to2M for block artifacts; native chunks remain capped100K). Existing `corpus-create` retains its65536-event declared cap. Inspection/candles/signals/account replay stream blocks, while complete source verification precedes checkpoint publication. Checkpoint cursors count artifacts, not internal blocks. Materialized CLI/review loading remains capped and can still allocate the complete Dataset; use corpus consumers for block-wise quote residency. Synthetic literal-USD execution remains the only integrated corpus execution scope.

## Verified preparation snapshot

Corpus replay uses `corpus::prepare` to combine full inspection with bounded closed causal multi-frame contexts. The primary and all higher frames share one aggregate1..2M candle budget. Borrowed primary candles also serve stop preparation and account replay. The snapshot is immutable in memory and is not a persisted current-source eligibility token. Artifact verification and saved-prefix semantic recomputation remain mandatory; this does not enable fast-seek, real/protected/non-USD execution or full-history acceptance. See DECISIONS/0046-verified-corpus-preparation.md and BENCHMARKS/prepared-pipeline-v1.json for exact scope and synthetic measurements.

Within a bounded corpus batch round, each worker retains one exact-bound preparation slot. Reuse rechecks every current artifact; paths, full specification limits, primary frame and candle cap are part of the binding. A changed binding drops the old buffer before construction. Batch `preparation` observations distinguish builds, replay reuses, attempted current-byte checks and maximum retained candles of an individual worker. These are not total RSS or hard resource limits. Slots currently end at each round. See DECISIONS/0047-worker-corpus-preparation-lifecycle.md.

## Foreground multi-round lifecycle

The `corpus-batch` foreground invocation now owns a `CorpusBatchSession` across its bounded rounds and releases buffers on exit. Every round still verifies actual source bytes and semantic checkpoint prefixes. Changed full inputs/limits, admission errors, worker failures or failed jobs release the old slots. Session `retained_candles()` reports retained candle objects only; independent simultaneous sessions do not share a global memory cap. A new process starts cold and resumes from registry evidence. Generated search callers still use the one-round API. This supersedes the earlier round-only slot lifetime; it does not enable fast-seek. See DECISIONS/0048-invocation-preparation-sessions.md.

Across-round retention also reserves the largest declared candle context for every effective worker. If the aggregate candle cap covers only the top-N unique jobs and cannot cover that retained worst case, the session releases old slots before assignment and uses normal bounded within-round preparation. This prevents duplicate large retained contexts during worker reassignment without refusing valid heterogeneous batches. Equal-budget pools retain their measured reuse path. This is a candle-object reservation, not total RSS or OS enforcement; see DECISIONS/0050-retained-worker-reservations.md.

The optional aggregate ceiling is centralized at `corpus::MAX_RETAINED_CANDLES` (2,000,000). Callers still declare their own context/concurrent budgets; existing defaults are unchanged. The continuous UTC2025/2026 synthetic stress check requires1,389,183 closed M1–D1 candles and verifies exact scalar/registered/cached receipts with measured release child resources. This is one artificial minute quote per minute with zero signals, not genuine tick coverage, economic evidence or real broker calendar approval. See BENCHMARKS/full-horizon-context-v1.json.

Batch key paths share a verified no-frame inventory, with exact source/path/operational bindings and full current artifact validation per consumer. This avoids duplicate candle hashing when only key facts are needed. inventory_byte_checks counts cold inventory attempts; current_byte_checks counts warm context attempts, not all reads. Supplied JSON cannot mint trusted snapshots; absent context refuses. Source/scientific approval and account-prefix verification are unchanged. See DECISIONS/0053-shared-verified-key-inventories.md and BENCHMARKS/shared-inventory-v1.md.

`corpus-source-facts SPEC` reports fully verified observed quote/source metadata without building candle hashes. Key paths now use this private-field, non-deserializable facts type; full inspection still includes all seven candle fingerprints. Every consumer rechecks current artifacts, and account preparation/prefix semantics are unchanged. Source facts establish no approval/coverage/qualification. The full-horizon check compares facts against complete inspection; see DECISIONS/0054-source-facts-without-candle-hashing.md.
